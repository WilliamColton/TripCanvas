# GPT Image Playground 需求分析报告

> 基于当前项目代码与 README 梳理，报告聚焦已实现能力、产品边界、用户角色、功能需求、非功能需求、数据对象、验收标准与风险建议。

## 1. 项目概述

GPT Image Playground 是一个面向图片生成与编辑场景的 Web 应用，当前由 React/Vite 前端与 Go/Gin 后端组成。系统通过后端统一接入 OpenAI Images API 兼容接口，提供文本生图、参考图编辑、遮罩局部编辑、任务历史、图片存储、用户登录、配额控制、邀请注册、兑换码、后台管理、计费统计等能力。

项目从早期“本地优先的浏览器图片生成工具”演进为“带账号、配额、端点池和运营后台的图片生成服务”。因此，当前需求重点不只是图片生成体验，还包括多用户隔离、资源管控、成本核算和后台运营。

## 2. 需求背景

### 2.1 用户痛点

1. 普通用户需要一个简单、可视化的界面调用图片生成模型，而不是直接编写 API 请求。
2. 图片生成参数较多，用户需要快速选择尺寸、质量、格式、压缩率、审核强度等参数，并能查看模型实际返回参数。
3. 图片生成通常是迭代式工作流，用户需要保存历史记录、复用提示词与参数、将输出图片继续作为参考图编辑。
4. 多用户服务需要限制使用量，避免无配额用户或并发请求耗尽模型资源。
5. 运营方需要管理用户、配额、兑换码、邀请、API 端点、定价、成本与收益数据。

### 2.2 项目目标

1. 提供稳定、易用的文本生图与图像编辑工作台。
2. 支持普通用户通过账号、密码、邀请或兑换方式使用服务。
3. 支持管理员配置 API 端点池，并根据图片尺寸、优先级、并发限制和失败切换调度请求。
4. 支持任务异步执行、状态追踪、失败提示和历史记录管理。
5. 支持按成功生成图片记录成本、收入和利润，为运营决策提供数据依据。

## 3. 系统范围

### 3.1 范围内

- 用户认证、注册、迁移、改名、改密、邀请码设置与邀请用户查看。
- 文本生图、参考图编辑、遮罩编辑、批量生成。
- 图片上传、图片读取、图片删除与用户隔离。
- 任务创建、任务列表、任务更新、任务删除、清空任务、任务状态流式更新。
- 用户配额校验、已用量统计、无限配额开关。
- 管理员登录、用户管理、兑换码管理、API 端点管理、定价配置。
- 公告、更新日志、反馈收集与管理。
- 计费记录、收入/成本/利润统计、按端点/用户/尺寸拆分分析。
- 前端响应式交互、主题切换、移动端适配。

### 3.2 范围外或当前未明确

- 在线支付、订单、发票和余额充值闭环。
- 团队空间、多人协作和共享画廊。
- 第三方 OAuth 登录。
- 图片内容审核的业务侧复核流程。
- 云对象存储、CDN、分布式队列与多实例横向扩展。
- 完整的审计日志、管理员操作日志和告警系统。

## 5. 业务流程

### 5.1 普通用户生成图片流程

1. 用户登录或注册进入应用。
2. 用户输入提示词，选择尺寸、质量、格式、压缩率、审核强度和生成数量。
3. 如需图像编辑，用户上传或复用参考图；如需局部编辑，用户绘制遮罩。
4. 前端提交任务到后端 `/api/generate` 或 `/api/edit`。
5. 后端校验参数、用户身份和配额。
6. 后端创建 queued 任务，并异步调用 API 端点池。
7. 任务获得并发槽后进入 running 状态。
8. API 返回图片后，后端保存输出图片、记录实际参数、记录计费数据、增加用户已用量。
9. 前端通过 SSE 或轮询获取任务状态，并在完成后展示输出结果。
10. 用户可收藏、搜索、复用、删除任务，或将输出图片加入参考图继续迭代。

### 5.2 管理员运营流程

1. 管理员通过后台 API Key 登录。
2. 查看用户列表，调整配额、启用/禁用用户、开启/关闭无限配额、重置密码或删除用户。
3. 创建或删除兑换码，供用户兑换配额。
4. 配置 API 端点池，包括 auto、1K、2K、4K 端点、优先级、并发上限和成本。
5. 配置销售定价，用于计算收入、成本和利润。
6. 查看计费统计，包括总体趋势、端点拆分、用户拆分、图片尺寸拆分和端点尺寸拆分。
7. 发布公告和更新日志，处理用户反馈。

## 7. 非功能需求

### 7.1 安全性

1. 受保护接口必须通过用户 JWT 或管理员 JWT 鉴权。
2. 用户资源必须按 `user_id` 隔离，包括图片、任务、配额和账号设置。
3. 密码必须使用安全哈希算法存储，不应明文保存。
4. 管理员接口必须与普通用户接口隔离。
5. 禁用用户不应继续调用生成、图片、任务等受保护接口。
6. 图片下载或展示接口通过 token 访问时，应控制 token 暴露风险。
7. 配置文件中的 API Key、JWT Secret 和管理员 API Key 应由部署方妥善保护。

### 7.2 性能与并发

1. 图片生成任务应异步执行，HTTP 提交接口不应阻塞到生成完成。
2. 端点池应支持最大并发限制，避免单个端点过载。
3. 多图生成可在兼容场景下并发发起，提高任务完成速度。
4. 上传内存限制应防止超大图片导致服务资源耗尽。
5. 任务列表、统计报表在数据量增长后应关注分页和索引优化。

### 7.3 可靠性

1. API 端点调用失败时，应根据优先级尝试后续端点。
2. 任务应具备 queued、running、done、error 状态，避免状态不明确。
3. 任务成功落库、用户用量增加、计费记录写入应保持事务一致。
4. 后端生成 goroutine 发生 panic 时，应捕获并将任务标记为失败。
5. 服务重启后，应处理未完成任务，避免用户看到永久 running 状态。

### 7.4 可维护性

1. 前后端应保持 Task、User、Image、Billing 等核心数据结构字段语义一致。
2. 后端参数归一化规则应有测试覆盖，避免前后端规则漂移。
3. 端点池、定价、邀请配置等运营配置应集中管理并可持久化。
4. 关键服务应保留自动化测试，包括鉴权、配额、任务、计费、端点失败切换。

### 7.5 兼容性

1. 前端应兼容现代桌面与移动浏览器。
2. 图片输入应支持常见格式，如 PNG、JPEG、WebP 等。
3. 系统应兼容 OpenAI Images API 的主流程。
4. Codex CLI 兼容模式应避免向不支持的接口发送 quality 等字段。

## 8. 数据需求

### 8.1 核心数据对象

| 对象 | 关键字段 | 说明 |
| --- | --- | --- |
| User | id、label、username、role、status、quota、usedCount、unlimitedQuota、passwordHash、inviteCode、invitedBy | 用户账号、配额和邀请关系 |
| RedemptionCode | id、code、quota、usedBy、usedAt、createdAt | 兑换码及使用记录 |
| Image | id、userId、filePath、mime、size、sha256、source、createdAt | 上传图、生成图、遮罩图的元数据 |
| Task | id、userId、prompt、params、inputImageIds、outputImageIds、status、error、elapsed、apiMode、codexCli | 图片生成和编辑任务 |
| Announcement | content、enabled、updatedAt | 前台公告 |
| Feedback | userId、category、content、contact、status、createdAt、updatedAt | 用户反馈 |
| ChangelogEntry | version、title、content、published、publishedAt | 更新日志 |
| BillingRecord | taskId、userId、endpointBaseUrl、imageSize、unitCost、unitSale、cost、revenue、profit、createdAt | 单张成功图片计费明细 |

### 8.2 数据保留要求

1. 用户删除任务不应必然删除历史计费记录。
2. 计费记录应保留用户标签、端点和单价快照，避免后续配置变化影响历史统计。
3. 图片文件与图片元数据应保持一致，避免孤立文件或失效引用。
4. 任务中的实际参数和改写提示词应作为结果追踪数据保留。

## 9. 外部接口需求

### 9.1 图片模型接口

系统通过后端调用 OpenAI Images API 兼容端点，主要能力包括：

- `/v1/images/generations`：文本生图。
- `/v1/images/edits`：参考图编辑和遮罩编辑。

端点配置应支持：

- Base URL。
- API Key。
- 最大并发数。
- 优先级。
- 按 1K、2K、4K 区分成本。
- 按 auto、1K、2K、4K 分池路由。

### 9.2 前后端 API 分类

| 分类 | 代表接口 | 说明 |
| --- | --- | --- |
| 健康检查 | `GET /api/health` | 服务可用性检查 |
| 公开配置 | `GET /api/config/public` | 前端启动配置 |
| 认证 | `/api/auth/*` | 登录、注册、迁移、改密、邀请码 |
| 图片 | `/api/images` | 上传、读取、删除图片 |
| 任务 | `/api/tasks`、`/api/tasks/:id/stream` | 任务列表、更新、删除、状态流 |
| 生成 | `/api/generate`、`/api/edit` | 文本生图和图片编辑 |
| 内容 | `/api/announcement`、`/api/changelog`、`/api/feedback` | 公告、更新日志、反馈 |
| 后台 | `/api/admin/*` | 管理员配置和运营管理 |

## 10. 约束与假设

1. 当前后端默认使用 SQLite 和本地文件系统保存数据与图片。
2. 当前服务更适合单实例部署；多实例部署需要额外处理任务调度、文件共享和并发状态。
3. 当前图片生成依赖外部模型端点，端点稳定性、响应速度和返回格式会直接影响用户体验。
4. 当前 CORS 配置允许所有来源，若用于公网生产环境，应根据部署域名收紧。
5. 当前 API Key、JWT Secret、管理员 API Key 依赖配置文件，生产环境应使用强密钥并限制文件权限。
6. 计费统计以“成功保存的输出图片”为准，不等同于外部模型实际扣费账单。
7. 图片生成结果可能包含模型改写提示词和实际参数变化，前端需要清晰提示用户。

## 11. 验收标准

### 11.1 普通用户侧

1. 新用户可通过有效邀请码注册并自动登录。
2. 已注册用户可通过用户名和密码登录。
3. 用户在有配额时可成功提交文本生图任务并看到任务从 queued/running 到 done 的状态变化。
4. 用户配额不足时无法创建任务，并能看到剩余配额不足提示。
5. 用户可上传参考图并完成图片编辑任务。
6. 用户可绘制遮罩并提交局部编辑任务。
7. 用户可查看、搜索、收藏、删除自己的历史任务。
8. 用户无法访问其他用户的图片或任务。
9. 登录态失效后，前端能清除 token 并展示登录入口。

### 11.2 管理员侧

1. 管理员可登录后台并查看用户列表。
2. 管理员可调整用户配额、启用/禁用用户、设置无限配额。
3. 管理员可创建兑换码，普通用户可使用兑换码增加配额。
4. 管理员可配置不同尺寸池的 API 端点，并保存后生效。
5. 当高优先级端点失败时，系统能尝试后续端点。
6. 任务成功后，后台统计能展示成功图片数、收入、成本和利润。
7. 管理员可发布公告和更新日志，前台能正确展示。
8. 管理员可查看用户反馈并更新处理状态。

### 11.3 系统侧

1. 后端服务启动后 `/api/health` 可访问。
2. 参数非法的生成请求会被拒绝，不会创建异常任务。
3. 并发提交任务不会绕过配额限制。
4. 任务完成时，任务状态、输出图片、用户用量和计费记录保持一致。
5. 服务重启后，未完成任务不会永久停留在 running 或 queued 状态。

## 12. 风险与改进建议

| 风险 | 影响 | 建议 |
| --- | --- | --- |
| 本地 SQLite 与文件系统不利于多实例扩展 | 横向扩展、容灾和备份能力受限 | 后续可引入 PostgreSQL、对象存储和独立任务队列 |
| CORS 全开放 | 公网部署时暴露面较大 | 生产环境按可信域名配置 CORS |
| 计费统计与真实供应商账单可能不完全一致 | 成本核算可能存在偏差 | 增加供应商账单对账或请求级外部 ID 记录 |
| 图片生成任务依赖内存中的 active task 状态 | 服务重启会丢失运行中任务控制 | 引入持久化队列和 worker 心跳 |
| 管理员操作缺少完整审计 | 难以追踪误操作 | 增加管理员操作日志和关键操作二次确认 |
| 大量任务和图片增长后列表性能下降 | 前台和后台加载变慢 | 增加分页、归档、清理策略和索引优化 |
| API Key 和 token 管理依赖本地存储/配置 | 存在泄露风险 | 强化密钥轮换、最小权限和安全部署文档 |

## 13. 后续需求优先级建议

### P0：稳定服务闭环

- 强化生产配置安全，包括 JWT Secret、Admin API Key、CORS、上传限制。
- 完善任务失败、取消、重启恢复和状态一致性。
- 保证配额校验、计费记录和用户用量事务一致。

### P1：运营能力增强

- 增加后台操作审计日志。
- 增加统计分页和导出。
- 增加端点健康检查、失败率统计和自动熔断。
- 完善邀请奖励和兑换码运营规则。

### P2：产品体验扩展

- 增加团队空间或共享画廊。
- 增加图片标签、文件夹或项目维度管理。
- 增加提示词模板和常用参数预设。
- 增加云存储、CDN 和跨设备同步能力。

## 14. 结论

当前项目已经具备完整的图片生成服务雏形：前台覆盖图像生成、编辑、历史记录和移动端体验，后端覆盖认证、配额、任务、图片、端点池、计费和管理后台。下一阶段应优先围绕生产安全、任务可靠性、运营审计和可扩展性进行加强，使其从单实例工具型应用进一步演进为可长期运营的多用户图片生成平台。
